# WebDAV 同步与自动签到

在 **设置 → 同步与自动化** 中配置。两个自动开关默认关闭，属于本机授权，不随备份传播。

## 连接与使用

1. 在 WebDAV 服务端创建一个目录，在各设备填写相同的完整目录 URL、用户名和应用专用密码，建议使用 HTTPS。
2. 保存后点击「立即同步」。应用在目录中维护 `s1er.s1backup.zip`；目录尚未创建会报错。
3. 可开启「启动时自动同步」：每次进程冷启动执行一次，不在切回前台时重复执行；失败不会阻止进入应用，可在设置查看结果并手动重试。
4. 仅在需要同步的设备上开启自动开关。退出程序前可手动同步一次，把本次阅读产生的改动上传。

文件直接复用 [L1 ZIP 备份格式](backup-format-v1.md)，也可下载后用原有「导入备份」恢复。同步范围为外观与功能偏好、所有本机账号的阅读历史与投票缓存、黑名单、置顶帖。Cookie、论坛登录凭据、WebDAV 凭据、草稿、图片缓存、本机路径及自动开关不上传。

WebDAV 连接信息保存在 `flutter_secure_storage` 对应的平台安全存储。HTTP 会明文传输凭据和备份，应优先使用 HTTPS；应用不会绕过证书验证，Native 不跟随重定向，Web 的重定向由浏览器处理，请直接填写最终目录地址。备份 ZIP 本身不加密，服务端应使用个人私有目录并限制访问。

## 合并规则

- **首次同步**：合并两端独有记录；同名设置/同键记录以云端为准。阅读进度始终取 `last_read_at` 较新的记录，不按最大楼层判断。
- **后续同步**：以本机上次成功同步的快照为基线，逐设置键、逐记录合并两端改动；单端改动（含删除）传播到另一端。双方都改同一项时本机优先，阅读进度仍取最近阅读。
- 置顶帖合并后超过本机 10 条上限时停止同步，提示先减少置顶，不会静默丢弃记录。
- 同步上传期间产生的本机新改动保留在本机，下一次同步上传。没有跨设备实时推送；只在启动或点击同步时交换数据。
- 本机合并基线和 WebDAV 连接不进入手动导出的备份；切换服务器目录或账号后按首次同步处理。

先下载、校验并合并，再条件上传，上传成功后才应用合并结果。首次创建用 `If-None-Match: *`，已有文件用服务器 ETag 和 `If-Match`。若另一台设备在下载后抢先更新，服务器返回 412，本次停止并保留本机数据，手动重试即可。文件损坏、格式过新、超过导入大小限制、认证失败、网络超时等均停止同步，错误文案不包含凭据。

标准服务走强 ETag 条件写入。坚果云等返回无引号 ETag 的服务走兼容路径：保留原值发出 `If-Match`，上传前重新下载并核对标识和完整文件，上传后读回核对；校验失败不应用云端设置、不更新本机合并基线。不会擅自给 ETag 加引号，也不会把 `W/` 弱标记去掉。服务器仍须提供可用的单个 ETag 并执行条件写入；完全缺失、弱 ETag、通配符或列表值会停止同步。额外的内容核验不能替代服务端的原子条件判断，建议避免多台设备同时点击同步。

条件写入遵循 [HTTP If-Match](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match) 和 [WebDAV ETag](https://www.rfc-editor.org/rfc/rfc4918.html#section-8.6)。应用不会无条件覆盖云端文件，也不会自动重试产生写入的请求。

### Web 端

WebDAV 直接连接用户配置的服务器，不通过论坛 CORS 代理。服务器须允许应用来源的 CORS：

- 方法：`GET`、`PUT`、`OPTIONS`。
- 请求头：`Authorization`、`Content-Type`、`Cache-Control`、`If-Match`、`If-None-Match`。
- 暴露响应头：`ETag`（`Access-Control-Expose-Headers: ETag`）。

安全存储需要 HTTPS 安全上下文（开发时可使用 localhost）。HTTPS 页面通常不能连接 HTTP WebDAV（浏览器混合内容限制）。

## 自动签到

开启「自动签到」后，启动并恢复已有论坛会话（或本次登录成功）时调用原有签到接口，不保存论坛密码，也不会为了签到主动重新登录。手动与自动签到共用请求锁和成功缓存；同一账号在本机日历日成功/已签到后，后续启动跳过。

失败结果保留在设置页，同一进程内同账号同日不自动重试，仍可在个人页手动签到。切换账号按各账号独立判断。开关关闭时仅保留原有手动签到行为。
