# WebDAV 同步与自动签到

在 **设置 → 同步与自动化** 中配置。自动同步与自动签到默认关闭，属于本机授权，不随备份传播。

## 连接与使用

1. 在 WebDAV 服务端创建一个目录，在各设备填写相同的完整目录 URL、用户名和应用专用密码，建议使用 HTTPS。
2. 保存后点击「立即同步」。应用在目录中维护 `s1er.s1backup.zip`；目录尚未创建会报错。
3. 「自动同步」可选 **关闭 / 仅启动 / 智能同步**。旧版已开启启动同步的设备仍保持「仅启动」，不会自动切换为智能同步。
4. 「仅启动」每次进程冷启动安排一次，失败后手动重试。「智能同步」还会在阅读、离开帖子及切回前台时择机同步，所有自动入口共用 **7 分钟最小尝试间隔**；手动「立即同步」可跳过冷却，成功后重新计时。

### 智能同步

- 阅读历史、设置、投票缓存、黑名单、置顶帖的本机变化会标记为待同步，连续切帖合并为一批。有改动且冷却到期时，等页面加载完成、停止滚动或离帖后空闲 2 秒再执行；持续阅读同一帖子也能定时保存。
- 没有本机改动时不定时请求。冷启动，以及离开应用至少 5 分钟后切回前台，会安排一次云端检查，仍遵守 7 分钟间隔，以接收其他设备的改动。
- 仅在前台安排任务。进入后台取消定时器，本地数据和待同步标记保留；下次恢复/启动继续处理，不依赖系统允许后台网络执行。
- 前三次尝试保持正常频次；连续第 3 次网络失败后，后续间隔为 **14、28、56、60 分钟**，最高 60 分钟。成功清零计数并恢复 7 分钟。尝试时间、失败次数与暂停状态保存在本机，重启不会绕过退避。
- 密码/权限、目录、文件格式和本机存储错误暂停自动尝试，修改连接或手动重试后恢复。版本冲突/临时锁定在后续机会重新下载、合并，不重发旧 PUT。
- 首页及主题列表顶栏的云朵入口显示同步中、待同步、成功或错误状态，点击查看详细信息和手动重试。自动任务不弹阻塞窗口或重复成功提示。
- 读帖期间合并的数据先落库，云端设置、黑名单等界面刷新延迟至所有读帖会话离开后应用；当前帖子不会主动跳转。上传期间的新改动仍留在待同步队列。
- 双方实际内容相同则跳过上传；导出时间等元数据变化不会单独触发 ZIP 改写。

文件直接复用 [L1 ZIP 备份格式](backup-format-v1.md)，也可下载后用原有「导入备份」恢复。同步范围为外观与功能偏好、所有本机账号的阅读历史与投票缓存、黑名单、置顶帖。Cookie、论坛登录凭据、WebDAV 凭据、草稿、图片缓存、本机路径及自动开关不上传。

WebDAV 连接信息保存在 `flutter_secure_storage` 对应的平台安全存储。HTTP 会明文传输凭据和备份，应优先使用 HTTPS；应用不会绕过证书验证，Native 不跟随重定向，Web 的重定向由浏览器处理，请直接填写最终目录地址。备份 ZIP 本身不加密，服务端应使用个人私有目录并限制访问。

## 合并规则

- **首次同步**：合并两端独有记录；同名设置/同键记录以云端为准。阅读进度始终取 `last_read_at` 较新的记录，不按最大楼层判断。
- **后续同步**：以本机上次成功同步的快照为基线，逐设置键、逐记录合并两端改动；单端改动（含删除）传播到另一端。双方都改同一项时本机优先，阅读进度仍取最近阅读。
- 置顶帖合并后超过本机 10 条上限时停止同步，提示先减少置顶，不会静默丢弃记录。
- 同步上传期间产生的本机新改动保留在本机，下一次同步上传。没有跨设备实时推送；按所选自动同步策略或手动操作交换数据。
- 本机合并基线和 WebDAV 连接不进入手动导出的备份；切换服务器目录或账号后按首次同步处理。

先下载、校验并合并，再按需条件上传，上传成功（或无需上传）后才应用合并结果。首次创建用 `If-None-Match: *`，已有文件用服务器 ETag 和 `If-Match`。若另一台设备在下载后抢先更新，服务器返回 412，本次停止并保留本机数据，智能模式等待后续机会重新同步，也可手动重试。文件损坏、格式过新、超过导入大小限制、认证失败、网络超时等均停止本次同步，错误文案不包含凭据。

优先使用下载响应中的强 ETag。下载头缺失、只有弱标记或格式不可用时，依次尝试同一文件的 `HEAD` 响应与 `PROPFIND`（`Depth: 0` 的 `DAV:getetag` 属性）。只接受目标文件、成功属性状态和 `DAV:` 命名空间中的版本信息，不借用目录或其他文件的 ETag。查询属性后会带 `If-Match` 重新读取并核对原下载内容，防止把新 ETag 错配到旧文件；上传后再读回核对。

坚果云等返回无引号 ETag 的服务走同样的内容核验路径：保留原始标识，兼容其 `+`、`/`、`=` 等 opaque 字符，不擅自加引号或去掉 `W/` 弱标记。校验失败不应用云端设置、不更新本机合并基线。如果三种读取方式都没有可用的单个 ETag，仍停止上传并明确提示，不无条件覆盖文件；通配符、弱标记和列表不能作为上传版本锁。服务器须执行条件写入，额外的内容核验不能替代服务端的原子条件判断，建议避免多台设备同时点击同步。

条件写入遵循 [HTTP If-Match](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match) 和 [WebDAV ETag](https://www.rfc-editor.org/rfc/rfc4918.html#section-8.6)。应用不会无条件覆盖云端文件，也不直接重发失败的 PUT；每轮自动重试均从重新下载、校验、合并开始，再按当前版本条件写入。

### Web 端

WebDAV 直接连接用户配置的服务器，不通过论坛 CORS 代理。服务器须允许应用来源的 CORS：

- 方法：`GET`、`HEAD`、`PROPFIND`、`PUT`、`OPTIONS`。
- 请求头：`Authorization`、`Content-Type`、`Cache-Control`、`Depth`、`If-Match`、`If-None-Match`。
- 暴露响应头：`ETag`（`Access-Control-Expose-Headers: ETag`）。

安全存储需要 HTTPS 安全上下文（开发时可使用 localhost）。HTTPS 页面通常不能连接 HTTP WebDAV（浏览器混合内容限制）。

## 自动签到

开启「自动签到」后，启动并恢复已有论坛会话（或本次登录成功）时调用原有签到接口，不保存论坛密码，也不会为了签到主动重新登录。手动与自动签到共用请求锁和成功缓存；同一账号在本机日历日成功/已签到后，后续启动跳过。

失败结果保留在设置页，同一进程内同账号同日不自动重试，仍可在个人页手动签到。切换账号按各账号独立判断。开关关闭时仅保留原有手动签到行为。
